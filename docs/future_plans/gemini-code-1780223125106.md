# 今後の開発方針およびロードマップ

## 1. 全体像とビジョン
本アプリは、日本のジム環境および日本のトレーニー（特にフリーウェイト初心者〜ミドル層）に最適化された、徹底的にシンプルでサクサク動く「ミニマルな筋トレ記録アプリ」を目指す。
多機能だが手数の多い海外製メガアプリ（HevyやStrong等）や、先行する国産アプリの隙間（不満点）をターゲットとし、「1セットのインターバル中に1秒で入力を終えられる直感性」と「ユーザー自身のデータの自由な管理・移行」を2大コア価値として提供する。

まずは開発コストとリスクを最小限に抑えるため、Windows環境およびGoogleのAI主導IDE「Anti-Gravity」を用いて「Android版」を先行リリースし、日本国内で 3,000〜5,000 MAU（月間アクティブユーザー）の獲得を最初のマイルストーンとする。

## 2. 実装を予定している主要機能（詳細と目的）
### ① 他社アプリ（筋トレMemo等）からのCSVデータ移行機能
- **目的：** 既存アプリのユーザーが「過去の記録（ログ）が消えるのが嫌だ」という理由で乗り換えを躊躇する心理的障壁（スイッチングコスト）を完全に解消する。
- **アプローチ：** ストア規約や安全性を考慮し、他社のデータ領域を直接覗き見るのではなく、ユーザー自身がエクスポートしたCSVファイルをアプリ内で手動インポート（選択）してもらう「ファイルインポート方式」を採用。プログラム側で列の並び順を解析し、自社データベースへマッピングする。

### ② 種目のフォーム・動作解説機能（フリーウェイト初心者向け）
- **目的：** 正しいフォームが分からない初心者が、ジムの現場で迷わず安全にトレーニングを実行できるようにする。
- **アプローチ：** - アプリ容量（MB）を肥大化させないため、高画質な動画ファイルをアプリ内に直接同梱することは絶対に避ける。
  - 基本仕様として、軽量な「アニメーションGIF」または「静止画イラストのステップ表示」をローカルに持ち、視覚的に一瞬でフォームの要点がわかるようにする。
  - より詳細な動的な解説を求めるユーザー向けには、YouTube API等を利用した「YouTube動画の埋め込み（WebViewまたはインライン再生）」を採用。これにより、アプリのバイナリサイズを最小限に抑えつつ、リッチな解説コンテンツを提供する。

### ③ 将来のマネタイズを見据えたUI/UXの事前設計
- **目的：** リリース初期は「完全無料・自動広告なし」という最高のクリーンさで定着率（リテンション）を高めつつ、後からの機能追加で既存ユーザーが離脱・炎上するリスクを防止する。
- **アプローチ：** 最初から画面最下部に「将来のスポンサーバナー用の余白（50px程度）」をレイアウトとして確保（初期は非表示、または自社ロゴを表示）。また、将来のプレミアム機能（有料メニュー）のためのボタンや導線をあらかじめ薄く配置し、タップ時に「今後のアップデートで追加予定」とポップアップを出すなどして、ユーザーに事前の心構えを作らせる。

## 3. 技術的要件と注意点
### ① アプリ容量（MB数）とサーバー通信費の最小化
- **オンデマンド配信の検討：** 初期のアプリダウンロード容量を数十MB以下に抑えるため、種目の解説画像やアニメーションGIF等の大容量アセットは、アプリ起動後または該当種目を初めて選択した際に、バックグラウンドでサーバーから個別にダウンロード（オンデマンド配信）する設計を検討する。
- **徹底したキャッシュ管理：** 一度読み込んだ動画インデックスや解説用画像データは、端末内のローカルストレージ（AsyncStorageやFileSystem等）に厳格にキャッシュし、ユーザーがジムでアプリを開くたびに無駄なAPI通信やパケット消費が発生しないようにする（通信費の削減および超高速な動作の実現）。

### ② iOS展開（App Store）を見据えたクロスプラットフォーム開発
- 現段階ではMacの購入コストを抑えるためにWindows＋Androidストア（Google Play）で先行するが、将来的に3倍以上の市場規模を持つiOSへシームレスに横展開（コードを共通化）できるよう、**React Native / Expo** をベースとしたクロスプラットフォーム言語での記述を絶対条件とする。
- 将来Mac環境を追加した際、Windows側で書いたコードをそのまま読み込ませるだけで一瞬でiOSアプリをビルド（書き出し）できる構造を維持すること。

### ③ 地域（ロケール）による広告・機能の動的制御
- 日本国内のユーザーに対しては、初期は広告を一切非表示（のちに1社限定の純広告スポンサー枠を配置）。日本以外の海外（英語圏）ユーザーに対しては、最初からGoogle AdMobなどのアドネットワーク広告が100%自動配信されるよう、端末の言語設定（ロケール判定）またはIPアドレス判定を用いた「条件分岐（If文）」を初期コードから仕込んでおく。

## 4. 開発ロードマップ（優先順位）

### フェーズ1：MVP（最小限の製品）の構築とAndroidリリース（最優先）
1. React Native / Expo による基盤構築（Androidターゲット）。
2. シンプルな重量・レップ数の記録画面、および種目選択画面の実装。
3. アプリ下部に「将来の広告・スポンサー用レイアウト枠」を固定（シングルトン設計）。
4. 「他社アプリからのCSVデータ移行機能」の実装（手動ファイル選択・インポート方式）。
5. 端末の言語設定による「日本＝広告なし」「海外＝AdMobあり」の自動切り替え分岐の実装。
6. Google Playストアへのリリースおよび日本国内での1,000〜3,000 MAUの獲得・バグ改修。

### フェーズ2：機能拡張とiOS展開・マネタイズ（中長期）
1. Androidでの手応え（目標：3,000〜5,000 MAU）達成後、中古Mac（M1/M2 Mac mini等）を導入し、App StoreへのiOS版リリース。
2. 初心者向けの「種目フォーム・動作解説機能（アニメーションGIF＋YouTube埋め込み＆オンデマンドキャッシュ配信）」の実装。
3. ガチ勢向けの「高度なデータ分析」「クラウド自動バックアップ」等のプレミアム機能（有料メニュー・サブスクリプション）の追加。
4. 日本国内の特定サプリメーカーやジムを対象とした「固定費型スポンサー（純広告）」の誘致、および事前確保していたバナー枠への流し込み。

## 5. 開発AI（Antigravity）への引き継ぎメッセージ・要望
**【Anti-Gravityへの指示事項】**
- **クロスプラットフォームの厳守：** 提示するすべてのコードは、将来のiOSビルドを想定した React Native (TypeScript) / Expo に準拠した形で生成してください。Android専用のネイティブコード（Java/Kotlin）を直接埋め込むことは避けてください。
- **データ設計の注意：** 筋トレ履歴データは、将来的にユーザーが自身のデータをMarkdown（テキスト形式）等でエクスポートしたり、Obsidian等の外部知識管理ツールと連携させたりしやすいよう、リレーショナルでプレーンな構造（SQLite等）を意識してスキーマを設計してください。
- **パフォーマンスと容量への配慮：** 「ジムの圏外や地下でもサクサク動く」を至上命題とします。アセットの読み込みやデータベースへのクエリは常に非同期かつ軽量に行い、メモリの消費（特にバナー広告の無駄なリロードによる規約違反やメモリリーク）が起きないクリーンなコンポーネント構造を提案してください。
